# 文藝部CMS 開発版

状態: ローカル検証済みの開発コード。本番は旧サイトのままです。
追加契約、支払い情報登録、Cloudflare D1/R2作成は行っていません。
このディレクトリを既存サイトのビルド対象に切り替えるのは接続・結合テスト後です。

## 今回実装したもの
- 既存公開サイトを維持したプレビューと、部員向け入口
- 公開内容だけを返す検索API（既存ページ側への接続は次工程）
- 会員・管理者ログイン画面、別々の共通パスワード、署名付きHttpOnlyセッション
- 作者IDの発行、作品情報登録
- 部誌・作品紹介・部長/副部長/メンバーの一言・イベント・店舗・お知らせの入力GUI
- 下書き保存、プレビュー、公開、公開取り下げ
- 同時編集時の上書き防止、管理操作の記録
- 会員作品検索、権限チェック付きPDF配信コード（R2接続後）

## 画面デモ
public/index.html をHTTPで配信し、URLに ?demo=1 を付けます。
公開画面には既存ホームを使用。右上の「部員の方へ」→部員ログイン→部員の本棚→「管理者へ」→管理者ログインの順です。
member-area.html が部員専用機能の入口です。別デザインの公開サイトは作りません。
デモでは架空の例だけを使用し、入力はタブ内のメモリだけに保持します。
再読み込みで消えます。ログインの入力は任意です。実際のDB保存ではありません。
module scriptを使うためファイルをダブルクリックする方式は対象外です。

## ローカル検証
```sh
node --test cms/test/core.test.mjs
```

SQLは migrations/0001_cms.sql を使用します。design/schema-draft.sql は旧案です。
wrangler.example.jsonc は接続設定の例で、現時点では有効なDB識別子を含みません。
秘密情報はMEMBER_PASSWORD、ADMIN_PASSWORD、SESSION_SECRETの3つです。
閲覧・管理パスワードは別々のランダムな16文字以上、署名用秘密は32文字以上とします。
ソースやこのREADMEに本物のパスワードを書かないでください。
パスワード変更で該当する既存セッションは無効になります。
セッションは8時間で期限切れ、ログイン試行はIPごとに15分で10回までです。
共通管理者パスワードなので操作した個人の識別はできません。
現在の試行履歴テーブルには期限切れ行の定期整理を運用段階で追加してください。

## 今後確認する点
1. Cloudflare既存Workerのビルド設定とプラン（コードからは不明）
2. 作品数・平均/最大PDF容量と年間増加。初期値は合意後に設定
3. 自動容量削除ではなく上限前の登録停止を初期方針とするか
4. 部誌の目次に載るがPDF未登録の作品も扱うか（推奨:扱う）
5. 一作品の作者は一人か、共著もあるか（現在のモデルは一人）
6. 作者IDを表示する管理用の名前は筆名でよいか
7. 一言の掲載名・代替わりで過去の一言を残すか
8. 店舗は販売/無料配布/閲覧のみを区別するか。地図リンクは任意
9. イベント終了後も過去の活動として掲載するか
10. 初期設定・バックアップ・復元を誰が引き継ぐか
11. 公開紹介・抜粋を確認する運営担当と、掲載内容の確定

確定済み: 管理者専用共通パスワード、一般検索は公開紹介/目次/抜粋のみ、
現役と卒業生は共通閲覧パスワード、PDFは閲覧を中心とする。
